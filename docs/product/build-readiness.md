The 4 Things to Lock Down Before Running /build
Before you hand this off to your coding agent (Claude Code, Cursor, Gemini CLI, etc.), we should nail down four exact inputs so the agent has zero ambiguity:

Platform & Tech Stack

Recommended for MVP: A mobile-first Progressive Web App (PWA) (e.g., React/Next.js + Tailwind CSS + browser Web Speech API for voice coaching + localStorage for memory). You can "Add to Home Screen" on your phone and use it immediately without fighting App Store/Play Store approvals.

Hard Domain Constraints (for CONSTRAINTS.md)

Zero side-lying exercises in the database.

Auto-balance rule: any session using the purple inner-thigh trainer must pair it with an outer-glute resistance band move.

Audio-first: screen stays awake (Wake Lock API) and voice handles all rep/rest/round cues; visuals only appear as a 5-second form check before weighted/banded moves.

The Exact Exercise Data Schema

AI agents are great at writing code, but terrible at inventing safe physiotherapy workouts on the fly. We should define the exact JSON structure (and your starter list of 30–40 exercises) with tags for mood, equipment, muscleGroup, voiceCues, and tempo.

Strict MVP Boundaries

In V1: 2-tap Mood/Time selector, Smart Workout Engine (with yesterday's memory), Voice Coach player, and the 1-tap post-workout pulse check (Easy / Just Right / Too Hard).

Out of V1: Login/accounts, cloud backend, custom music player, and complex analytics.
